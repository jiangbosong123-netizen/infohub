# NLP 情报模块演进方案

InfoHub 不只是一套新闻页面。它在未来大系统中的职责是把公开信息变成可追溯的结构化
事件，为宏观判断、公司影响分析、情感分析和其他智能体提供输入。

## 当前能力边界

已经具备：多源采集、原始链接、公司识别、主题归类、AI 翻译与筛选、稳定事件、真实
发布方统计、日报和运行健康监控。

需要继续建设：版本化 NLP 记录、情感方向、影响对象与期限、宏观主题、证据强度、模型
质量评估、任务审计和面向大系统的权限控制。

## 数据分层

```text
原始层        items.raw_summary / 原标题 / URL / 发布方 / 时间
清洗层        标准时间、去重、公司实体、频道和主题
事件层        stories + story_items，合并同一事件的多家报道
分析层        nlp_results，按分析类型和流水线版本保存输入证据与输出
服务层        /api/v1/items、/stories、/topics
应用层        InfoHub 页面、宏观分析、情感分析、未来的大系统
```

原始层字段不因模型更新而覆盖。当前页面使用的标题、摘要、评分仍保留在 `items` 中作为
高效查询投影；每次新策展结果同时写入 `nlp_results`，记录分析类型、流水线版本、模型、
输入证据、结构化输出和生成时间。

## 情感分析的正确粒度

情感分析应主要作用在事件和受影响实体上，不能把文章语气简单当成市场影响。例如“公司
裁员”对成本可能偏正面、对员工和需求预期可能偏负面。建议输出：

- 受影响公司、行业和宏观主题
- 方向：正面、负面、中性或混合
- 强度与置信度
- 时间范围：即时、季度或长期
- 影响路径与支持该结论的原文证据
- 是否有独立发布方交叉验证

同一事件的多篇报道先合并，再形成事件级结论，避免转载数量被错误当成多次情绪信号。

## 宏观分析的结构

宏观分析建立在主题和事件之上，第一阶段聚焦可解释维度：AI 资本开支、算力与芯片、模型
竞争、监管、企业软件采用、机器人商业化、科技就业和融资环境。每个结论必须能回到具体
事件和原始来源，并区分事实、模型判断和推测。

## 实施顺序

1. **集成底座**：正式迁移版本、`nlp_results`、只读 API 和游标分页。
2. **分析审计**：补充任务状态、失败类型、耗时、模型与提示版本；为历史数据按需回填。
3. **情感分析 v1**：建立人工标注样本，先做事件级公司影响方向与置信度。
4. **宏观主题 v1**：事件映射宏观因子，生成带证据的日/周变化摘要。
5. **大系统接入**：API 身份认证、限流、增量游标、契约测试和数据保留策略。

每一阶段独立 PR、独立验收。未合并分支不进入 Windows；合并后由 Windows Server Manager
自动部署，再通过 `/api/health` 和 `/api/v1` 接口核对版本与数据。
