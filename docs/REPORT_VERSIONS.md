# Reproducible reports: schema foundation (P21a)

Migration 19 adds four empty tables. It leaves `daily_reports` untouched and
does not switch the generator, worker, portal, or API. A legacy report's text
and timestamp remain available exactly as before; the P07 legacy identity is
not retroactively treated as a reproducible report.

`report_input_snapshots` fixes the report type, date, window bounds and basis,
time zone, optional market-calendar ID/version, `as_of`, optional knowledge
checkpoint, and a SHA-256 digest of the complete input manifest. A future
builder must put the exact selected titles, excerpts, timestamps, source URLs,
scores, curation publication IDs, and selection-rule version in that manifest.
`report_input_members` ties each ordered material to a legacy item or stable
document version and records a digest of the actual material. A report version
can only be inserted when the declared member count is complete; the snapshot
and members cannot be changed or deleted, and no member can be added after a
version references the snapshot.

`report_versions` appends a numbered result for the same report key and
dataset. Each revision names its immediate predecessor, generation mode,
content digest, citations, coverage, timestamps, and model/prompt identity
when generated by an LLM. Versions cannot be updated or deleted.
`report_publications` is the sole mutable pointer for selecting a version;
the database rejects a pointer to a different report key or dataset. This
lets a later implementation retain a good published version if generation or
validation fails, and switch back without deleting history.

P21b must add the builder and validate JSON/hash/citation semantics before
writing; SQLite only validates structure and foreign keys. P21c will add
legacy backfill and a guarded portal read switch. P21d will move the scheduled
generator behind this versioned write path. Natural-day windows and future
US market-session windows are separate report types; no market calendar is
invented by this migration. The current legacy generator can still overwrite
`daily_reports` until that later cutover, so this PR does not claim P21 is
complete. No Windows production migration has been run.

The [isolated Mac-copy rehearsal](evidence/p21a-report-schema-rehearsal.json)
staged prior migrations 1–18, then applied only migration 19. All 8 legacy
reports and item rows retained their before/after digests, SQLite integrity
was `ok`, and foreign-key violations were zero. Because the Mac source was
unversioned, this is a staged-copy check rather than a Windows production
18-to-19 rehearsal; deployment still requires a fresh Windows backup and
isolated-copy verification.
