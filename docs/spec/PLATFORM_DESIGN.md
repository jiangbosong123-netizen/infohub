# 投研平台总体设计：一个大系统，两个方向

> 版本：v1（2026-10-15）。所有者在对话里逐条确认了第一节的决定，记为 [D31](DECISIONS.md)。
> 本文件定的是 Infohub 这一侧要做什么、怎么交给另外两个系统；两个系统内部怎么改，由各自的仓库按各自的规矩决定，
> 本文只写建议与接口约定。

## 一、已经定下的事（所有者 2026-10-15）

1. **一个大系统，两个方向，各自独立产出，不合并结果。**
   - **因子实验室**（`jiangbosong123-netizen/factor-lab`）：量化对冲，找超额。美股大中盘全行业，每月约 1,000–1,500 只。
   - **AI 半导体投研系统**（`jiangbosong123-netizen/AI-investment-research-system`）：跟踪 AI 算力产业链，挖掘被市场低估的公司。
     决策池 62 只，加 8 只观察；以后可能扩到别的行业。
2. **共用底座**，包括：
   - 统一的公司身份表，三个系统都用 SEC 编号（CIK）作公司编号；
   - Infohub 作为"全市场新闻与情绪层"；
   - 一个通用查询接口；
   - 一个只看运行状态的总控台（卡片的改动暂缓，先定本设计）。
3. **Infohub 的覆盖范围按市场来划，不跟任何一方的名单绑定。** 谁要数据，带着自己的名单来查；改名单只改查询参数，Infohub 不用改。
4. **范围慢慢扩**：一档一档放大，每档实测之后再进下一档（第四节）。
5. 两个系统怎么用这些信息，按第五节的方向做，但都要**先影子运行、先检验**。动仓位必须由所有者确认，系统不自动下单。

## 二、三个系统的现状（2026-10-15 核对）

**因子实验室**
- **在做什么：** 量化层的因子研究池，按月逐只筛选，每月约 1,000–1,500 只。名单规则见该仓库的 `名单规则.md`：交 10-K、在 NYSE/Nasdaq 上市、价格 ≥5 美元、日成交额中位数 ≥1,000 万美元、市值 ≥10 亿美元、不是非经营实体。
- **新信号怎么进来：** 先写预注册，再取数。面板列是月末日期 `d`、`cik`、`下月收益`、`信号`、`可得日`，框架自己检查时点。检验指标是月度截面 IC 的 t 值（多重检验校正），并要求扣成本后的多空收益为正。
- **与 Infohub 的关系：** 名单**故意排除了投研系统的 62 只**（规则 ⑥），两边样本不重叠，平台必须保留这道防火墙。以前因为新闻数据要花钱，否掉过新闻情绪类因子。
- **看板：** `看板.py`，本机 8767 端口，已经设计成总控台，读"状态 v1"。

**AI 半导体投研系统**
- **在做什么：** 每天给每只股票评级（+3 到 −2），由模块分加权合成，风险只能否决。2026-10-12 选股超额检验未通过之后，定位转为风险控制与监控工具。
- **和新闻有关的空缺：**
  - 模块 4"事件与信息研究"设计了新闻证据，格式是方向、强度 1–5、影响时长、事实/观点/预测/传闻、可信度、原文引用，但现在只有 SEC 8-K 一种来源；
  - 模块 5"市场情绪"现在只有价格动量。
- **新规则怎么进来：** 先预注册、多重检验校正、按时点不偷看；规则版本号要变，并经所有者批准。量化层不能写回核心层。
- **看板：** 本机 8766 端口。

**Infohub**
- **在做什么：** 新闻采集、AI 相关性评分、事件聚类、主题和日报，已经部署在 Windows 上。
- **已有的：** 情绪（tone）和影响（impact）的数据契约、分析账本、带密钥和审计的 v1 接口、按时点同步的快照。
- **还没有的：**
  - 情绪模型、信号表和信号接口都还没有生产数据；
  - 现在只覆盖 23 家公司（13 只美股、8 只港股、2 家未上市）；
  - 文档的"可用于回测"标记全是假；
  - 没有交易日历。

## 三、共用底座

### 3.1 统一的公司身份表（CIK 为主键）

- **来源：** SEC 的 `company_tickers_exchange.json`（CIK、代码、交易所），加上每家公司的 submissions（SIC 行业代码、曾用名）。每天自动更新。
- **保留历史：** 代码变更、更名、分拆的历史都要留着，因为老新闻里出现的是旧代码。
- **别名：** 每家公司配一份别名表，有中文名的也挂上。和常用词撞名的公司（如 Apple、Target、Visa、Gap）单独标记，识别时要更严格（见 3.2）。
- **各系统自己的编号：** 由各系统自己映射到 CIK。投研系统的 `C-000001` 这类编号，在它那边映射。
- **在 Infohub 里的位置：** 建在现有的版本化身份目录（`entities`、`entity_identifiers`、`security_listings`）上，不另起一套。

### 3.2 Infohub：全市场新闻与情绪层

**采集：按覆盖范围采，而不是逐家搜**

| 来源 | 覆盖方式 | 说明 |
|---|---|---|
| SEC EDGAR 全市场申报流 | 一条流盖住全部公司，按覆盖范围过滤 | 已有 SEC 采集，改成全市场 |
| 按股票代码订阅的新闻源 | 覆盖范围内每家一个订阅，节奏随家数调整 | 家数多时降低频率 |
| 公司新闻稿发布渠道 | 全市场 | 发布方是公司本人，独立性高 |
| 现有快讯和媒体源 | 不变 | 财联社、新浪、华尔街见闻、科技媒体等 |
| Google News 逐家搜索 | 只给一份可随时修改的"重点关注"配置 | 这份配置只影响多搜一点，不影响数据结构 |

**识别：每条新闻涉及哪些公司**
- 依据：股票代码（含 `$NVDA` 这类写法）、公司名和别名、上下文。
- 撞名公司必须同时出现代码，或者上下文里出现行业词，才算命中。
- 每次识别都记下置信度。认不出的不硬塞，留着以后复核。

**判断：每条新闻 × 每家涉及的公司，给出一条证据**

| 字段 | 取值 |
|---|---|
| 方向 | 正面 / 中性 / 负面 / 混合 / 证据不足 |
| 强度 | 1–5 |
| 影响时长 | ≤1 周 / 1 周–1 季度 / >1 季度 |
| 内容性质 | 事实 / 观点 / 预测 / 传闻 |
| 事件类型 | 业绩与指引、管理层、并购、监管与诉讼、产品、产能与供应、资本开支、评级调整、做空报告等 |
| 原文引用 | 能回到原文核对的那句话 |
| 可信度 | 0–1，校准之前只作参考 |
| 模型与提示词版本 | 换了模型，旧结果不改，新旧分开记 |

这些字段**刻意和投研系统模块 4 的证据格式一一对应**，那边拿来就能用。

为了控制费用，判断分两层：
- **第一层：** 所有新闻做便宜的公司识别和粗分类。
- **第二层：** 只把重要的交给大模型深度判断。"重要"按新闻本身的重要程度和公司规模来定，**不按它在谁的名单上**。

**时间与去重**
- **可得时间** = Infohub 第一次看到这条新闻的时间，回测只能用它。新闻自己标的发布时间只用于显示。
- 晚上关机期间的新闻，可得时间是开机后补抓到的那一刻。这是正确的时点，不要往前改。
- 同一件事被转载多次只算一次，用现有的事件聚类。每条证据标明是原始报道还是转载，以及发布方是谁。
- 情绪要在收到新闻时就打分，并记下模型版本。事后补打分时，必须确认模型的知识截止日期早于新闻日期，否则模型可能"已经知道结果"，回测就不干净。

### 3.3 通用查询接口（v1，`read:signals` 权限）

调用方带着自己的 CIK 名单来查。**Infohub 不保存任何一方的名单。**

| 接口 | 输入 | 输出 | 主要给谁 |
|---|---|---|---|
| 证据查询 | CIK 名单、时间段、`as_of` | 逐条证据（3.2 的字段）+ 新闻标题、链接、发布方、可得时间 | 投研系统 |
| 汇总查询 | CIK 名单、日期区间、窗口长度、`as_of` | 每家公司每天的数值：新闻数、独立来源数、平均情绪、正负面条数、关注度异常（和自己过去比）、各类事件次数 | 因子实验室 |
| 状态 | — | "状态 v1"格式：各项是否正常、关键数字、数据新鲜度 | 总控台 |

- 所有数值都只用"可得时间 ≤ `as_of`"的新闻来算。同一个 `as_of` 什么时候查，结果都一样。
- 汇总里新闻数太少的公司，分数给空值，不给 0。
- 每个数值都带上算法版本号。

### 3.4 总控台

- 短期：因子实验室的看板读三个系统的"状态 v1"，不合并任何结果。卡片的改动等本设计确认、Infohub 的状态接口做好之后再做。
- 长期：三个系统的看板都放到常开的 Windows 上，用 Tailscale 私网访问，手机上一个地址能看全部，每个也能单独打开。

## 四、覆盖范围怎么扩

每一档都按**市场规则**来划，不按名单。每档跑 1–2 周，下面四项都过关才进下一档：

1. 每天的新闻条数；
2. AI 费用；
3. 硬盘每天涨多少；
4. 识别准确率：每档抽 50 条人工核对，认错率 < 5%。

| 档 | 新增范围（市场规则） | 大约家数 | 用途 |
|---|---|---|---|
| 0 | 现有 23 家 | 23 | 现状 |
| 1 | 半导体及 AI 算力产业链：Nasdaq 行业分类里的半导体、电子元件、计算机制造与外设、计算机通信设备，以及科技板块里的工业机械、电气产品、电信设备，市值 ≥10 亿美元；再加覆盖申请 | 144（2026-10-15 实测，含精选名单里已有的 11 家） | 盖住投研系统现在的池子（70/70） |
| 2 | 美股市值前 100 | 累计 214 | 新闻最多的大公司，也是因子实验室的头部 |
| 3 | 市值前 500 | 累计 584 | 因子实验室的核心 |
| 4 | 因子实验室的市场规则（10-K 申报、NYSE/Nasdaq、市值 ≥10 亿美元、经营实体） | 约 1,000–1,500 | 因子实验室全池 |
| 另加 | 投研系统扩到的新行业，例如国防、材料、能源 | 按行业 | 随投研系统 |

- **第 1 档实际怎么划（2026-10-15 定稿，`config/coverage.yaml`）：**
  - 改用 Nasdaq 股票筛选器的行业分类，而不是 SIC。原因有两个：一是它一次请求就能拿到全部约 7,000 只股票的行业和市值，SIC 却要逐家去取 SEC 档案（实测约 3 秒一家）；二是投研系统的 70 只散在 21 个 SIC 代码里，其中有"软件"这种几百家的大类。
  - 这条规则盖住 70 只里的 55 只。剩下 15 只是 5 家云厂商（第 2 档本来就有）、芯片设计软件、Entegris、Quanta、Modine 等跨行业公司，由投研系统的**覆盖申请**补上。
  - 覆盖申请就是 `config/coverage.yaml` 里的一份 CIK 名单：只决定多采哪些公司，不进数据结构；名单变了只改这份配置，不改代码。
  - SIC 仍然只为被覆盖的公司取，存进 `security_industry_codes`，留给以后按 SIC 划的档（比如第 4 档去掉基金和 SPAC）。
- **前提：** 进第 3 档之前，必须先解决 Windows 硬盘空间（C 盘剩 31 GB，见第七节）。
- 港股、中概股的现有采集不变。

## 五、两个方向怎么处理 Infohub 的信息

以下是给两个系统的建议用法。具体规则写进各自仓库，各自预注册、各自检验。

### 5.1 投研系统（跟踪行业、挖低估）

| 用法 | 进哪里 | 怎么处理 |
|---|---|---|
| 事件证据 | 模块 4 事件分 | 逐条证据按它已设计的公式计分：时间衰减、去重、只算原始来源和独立研究。补上现在只有 SEC 8-K 的空缺 |
| 风险预警 | 模块 6 风险分、闸门 | 统计负面新闻密度。诉讼、出口管制、做空报告、下调指引、财务问题这类重大事件，提示所有者人工复核 |
| 行业景气 | 模块 2 | 整个行业的新闻按主题汇总，比如 AI 资本开支、产能与供应、出口政策；另出每日行业简报 |
| 挖低估 | 新的"候选清单"，只给人看 | 新闻情绪代表"市场怎么看"，基本面分代表"实际怎么样"。基本面在变好、新闻却冷淡或偏负面，或者没人报道的，列为"可能被低估"；新闻很热、基本面没跟上的，提示可能过热 |

- 先进影子评级（v2 影子引擎），不影响正式评级。
- 要进正式评级，必须按它的量化层规范预注册、检验通过，规则版本号变更，并经所有者批准。
- 候选清单只是研究线索，不自动改评级。

### 5.2 因子实验室（量化对冲、找超额）

| 信号 | 定义（以预注册为准） |
|---|---|
| 情绪水平与变化 | 窗口内新闻的平均情绪，以及相对自己过去的变化 |
| 关注度异常 | 新闻数相对自己过去的偏离 |
| 事件信号 | 指定事件类型的次数，例如下调指引、管理层变动、监管调查 |
| 风控叠加 | 已通过的组合里剔除负面新闻异常的股票，检验能否减少回撤 |

- 每个月末，只用可得时间早于月末的新闻，按实验室名单取汇总；按行业和规模调整之后，生成面板（`d`、`cik`、`信号`、`可得日`），再走实验室的检验框架。
- **说实话的部分：**
  - 研究上，新闻信号的作用通常只持续几天到几周，按月调仓可能太慢，建议实验室另设一个"按周检验"的版本。
  - Infohub 从 2026-09-11 才开始有数据，要先攒几个月以上，检验才有意义。所以**预注册要尽早写**，数据从现在开始攒。
- 实验室名单排除投研系统的 62 只。查询时由实验室带自己的名单，防火墙自然保住。

## 六、共同规矩

1. 回测只用可得时间，不用发布时间。
2. 同一件事只算一次，每条证据标明来源独立性。
3. 每个判断带模型和算法版本；换模型不改旧结果。
4. 情绪准确率要先验证：所有者盲标约 200 条（按 [D23](DECISIONS.md) 的"所有者标注"层级，结论只算实验性），每档扩展和每次换模型后抽查。
5. 先影子运行，先检验；任何影响评级或仓位的规则，都要预注册、检验通过并经所有者批准。
6. 系统只给证据和建议，不自动下单。

## 七、代价与风险

| 项 | 说明 | 对策 |
|---|---|---|
| AI 费用 | 覆盖面扩大后新闻量可能是现在的数倍 | 两层判断；每档实测，超出预算就停在当前档 |
| 硬盘 | Windows C 盘剩 31 GB；按现在的量数据库每月就要涨几个 GB，扩大后更快 | 进第 3 档前必须解决：查清 C 盘占用（游戏本，已用 895 GB），清理或加外接固态硬盘；低重要度新闻只存精简记录 |
| 识别认错 | 公司越多，撞名越多 | 撞名公司从严判断；记录置信度；每档抽查 |
| 信号短命 | 新闻效应多在几天到几周内 | 实验室加按周检验；投研系统主要用于风险和候选清单 |
| 历史太短 | 数据从 2026-09-11 起 | 尽早预注册，攒够再检验；不拿短样本下结论 |
| 模型偷看未来 | 事后补打分时，模型可能已经知道结果 | 收到即打分；补打分只用知识截止早于新闻日期的模型，并记录版本 |
| Windows 晚上关机 | 夜间新闻可得时间推迟到开机后 | 这是真实时点，照实记录；需要更完整的覆盖时再考虑常开 |

## 八、分步计划

| 步 | 内容 | 在哪个仓库 | 交付与验收 |
|---|---|---|---|
| M0 | 本设计确认 | Infohub | 本文件合并 |
| M1 | 公司身份表，第 1 档采集与识别 | Infohub | 第 1 档覆盖投研系统 62 + 8 只；抽查 50 条，认错 < 5%；新闻量、费用、硬盘实测 |
| M2 | 公司级证据判断（3.2 的字段），证据查询接口，状态接口 | Infohub | 所有者盲标约 200 条，报告准确率；证据接口按时点查询的结果稳定 |
| M3 | 投研系统影子接入：模块 4、6、2 和候选清单 | 投研系统 | 由那边按自己的规矩预注册、影子运行，Infohub 配合 |
| M4 | 汇总查询接口；因子实验室预注册新闻类假设 | Infohub + 因子实验室 | 汇总值按时点可复现；预注册在取数之前提交 |
| M5 | 第 2、3 档扩展（先解决硬盘）；总控台卡片 | Infohub + 因子实验室看板 | 每档四项实测过关 |
| M6 | 第 4 档扩展；看板搬到 Windows（可选） | 三个仓库 | 视费用与硬盘决定 |
